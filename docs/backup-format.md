# 收藏备份格式

收藏页与设置中的“导入收藏记录 / 导出收藏记录”使用 Android 系统文件选择器。保存 JSON 后，可以在另一台设备或全新安装中恢复；不需要旧应用的数据库文件。

备份包含全部本地帖子收藏夹（名称、顺序、封面）、帖子元数据、每条收藏夹关系、标签收藏和所有本地标签备注。一个帖子可以属于多个收藏夹；没有收藏但单独写过备注的标签也会导出。文件不包含视频/图片文件、账户凭据、Cookie、普通设置或浏览历史；导入不会恢复这些数据，也不会改动现有下载文件。

## 当前格式

UTF-8 JSON，最大 20 MiB。文件开头的 UTF-8 BOM 可以识别。

```json
{
  "format": "sakugapp.library",
  "schemaVersion": 3,
  "folders": [
    {"key": "folder_0", "kind": "default", "name": "", "position": 0},
    {"key": "folder_1", "kind": "custom", "name": "Study", "position": 1, "coverPostId": 123}
  ],
  "posts": [{"savedAt": 1760000000000, "post": {"id": 123, "tags": []}}],
  "links": [{"postId": 123, "folderKey": "folder_1", "addedAt": 1760000000000}],
  "tagFavorites": [{"name": "original_tag", "category": "ARTIST", "savedAt": 1760000000000}],
  "tagNotes": [{"name": "not_favorited", "note": "Local note", "updatedAt": 1760000000000}]
}
```

上例只说明格式，不是可用的网站帖子数据。实际 `post` 快照含已取得的原始标签、Score、缩略图和文件 URL、Source 等字段；缺失字段可以省略或为空，不补造数值。URL 只允许 HTTPS Sakugabooru 媒体地址。网站帖子 ID 是网站的持久身份；收藏夹 `key` 仅在当前备份中标识关系，作为不透明字符串处理，不是 Room 数据库 ID。`kind: default` 标识默认收藏夹，其名称为空；其他收藏夹必须有名称。导入会重新分配本地收藏夹 ID。

文件限制：最多 100 个收藏夹、10,000 个帖子、50,000 条收藏关系、5,000 个收藏标签和 5,000 条备注。帖子快照总量最多 8 MiB；标签名最多 200 字符，收藏夹名最多 80 字符。备注最多 500 个 Unicode 码点、8 行，按应用现有规则规范化换行与控制字符。未知标签分类保持 `UNKNOWN`，不根据名字猜测。

## 合并与冲突

导入先完整解析、校验并展示收藏夹/帖子/标签/备注数量，然后才写入；不支持的版本、损坏文件、无效关系、无效封面、超限内容均拒绝。实际写入与限额检查位于同一个 Room 事务中，失败不会留下部分数据。

默认合并，不清空本地数据：

- 同名收藏夹按忽略大小写的名称与出现次序逐一合并；备份中不同 key 的同名收藏夹保持独立，重复导入也不把它们合成一个。保留本地名称、顺序和已有封面，缺少封面时才使用备份封面。不同名的新收藏夹按备份顺序追加。空数据库恢复会保留备份中的完整顺序，包括默认收藏夹的位置。
- 也可以明确选择保留两份同名收藏夹；新副本加 ` (2)` 等后缀，不覆盖旧收藏夹。此选项有意创建副本；重复导入一般应选择默认合并。
- 帖子按网站 ID、标签按原名、收藏关系按“网站帖子 ID + 目标收藏夹”去重。已有帖子快照、保存时间和关系不替换。已知分类可以补全本地 `UNKNOWN` 分类，已知分类不互相覆盖。
- 已有备注默认保留；需要替换时必须明确选择。未收藏标签的备注同样恢复；取消收藏与清除备注互不影响。
- 预览展示同名收藏夹及不同内容备注的冲突数量。用户确认后，会按当前数据库重新计算合并，避免预览期间的新数据被隐式覆盖。

导入结果中的成功/跳过按独立记录计数，包括收藏夹、帖子快照、收藏关系、标签收藏和备注。替换备注或补全分类计为成功；已存在且保留的记录计为跳过。成功返回时失败数为 0；任何校验或事务失败都会使整次导入失败，显示成功 0 / 跳过 0 / 失败 1（整个文件）及原因，并保留本地原数据。

## 旧格式

继续接受 `format: sakugapp.library`、`version: 1` 或 `version: 2` 的旧 JSON。旧版 `folders[].id` 与 `links[].folderId` 只用于解析该文件内部关系，导入仍重新映射到目标数据库；不要求安装旧应用或保留原数据库 ID。旧 `position`、有效封面和多收藏夹关系会保留；旧应用可能留下已移出收藏夹的失效封面引用，导出或 v1/v2 导入会将该引用置空，其余数据继续恢复；新格式的失效封面作为损坏文件拒绝。更旧文件没有 `position` 时使用文件顺序。旧文件中 id 1 始终按默认收藏夹处理，旧的自定义默认标题规范化为空名，由界面显示当前语言的默认名称。version 1 没有标签收藏/备注数组；version 2 支持二者。废弃字段不再导出。

新备份使用 `schemaVersion`，不再写 `version`。旧版应用未必能读新格式，请保留升级前的旧备份。

## 验证

- `BackupImportTest`：可移植键映射、真实旧格式形状、默认冲突策略、重复导入、独立备注、顺序/封面、多对多关系、严格 JSON/版本/大小/关系校验。
- `BackupRestoreDeviceTest`：从源数据库导出后关闭源库，在全新的持久数据库中导入、逐项核对并重新打开；同时验证旧格式合并、备注冲突选择、媒体时长/历史不变、损坏及容量失败不修改原数据。
- `LibraryCodecTest` / `PersonalDataTest`：现有真实公开帖子样本、分类、备注及旧格式回归。

实际执行结果及 CI 链接记录在本轮开发记录中；测试存在不等于已在设备运行通过。
