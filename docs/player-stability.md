# 播放与标签布局增量

开发分支 `dev/player-stability-controls`；版本保持 1.2.0 / code 13，不创建 Release。

没有用户设备的崩溃堆栈，不能确定其崩溃根因。本轮针对代码确认的风险调整：

- 播放器曾在 lifecycle owner 改变时释放，但 `remember(url)` 仍可能返回同一已释放对象。现在释放绑定播放器实例，页面暂停时停止解码/缓冲，重新可见时恢复进度与播放意图；进度轮询也随 lifecycle 停止。
- 播放设置/时间定位 effect 加入播放器作为 key。全屏使用 `switchTargetView` 转移 Surface，不新建播放器；全局播放焦点停止旧播放，媒体缓冲限制为预览 8 MiB、详情 24 MiB，时间缓冲上限 15 秒。
- Posts 每个查询保留最近加载的 600 条；稳定 ID 作为网格 key，继续分页，不保存无限历史页面。详情退出释放本地邻帖序列；预览状态不再写入网格的长期 saveable 状态。
- Coil 内存缓存取堆容量的 15%，最多 48 MiB；原图片磁盘缓存目录保留，上限 128 MiB。A–B 定位仍按 30 ms 检查，文字进度更新降至 250 ms。限制截图并发，避免反复申请大 Bitmap。

预览标签使用独立紧凑行高并移除原固定 3 dp 上下 padding，0 dp 只有必要文字行高；范围改为 0–20 dp，同时用于长标签内部换行与 FlowRow 行间距。未设置时默认 16 dp 以接近旧视觉高度；已有保存值保留。详情和其他标签不使用此紧凑样式。

收藏夹选择改为整行可点击的圆角浮块，保留多收藏夹、取消及新建。全屏默认仅显示视频；确认的单击切换控制界面，双击/滑动/双指手势保持独立，原生进度条和按钮优先处理自身输入。已知视频尺寸决定首次全屏方向；未知时等待解码尺寸，不猜测横屏。手动旋转后不再被自动方向覆盖。错误保留，主动显示控制界面后可查看和重试。

本地执行定向窗口测试、资源检查、Lint、Debug 与测试 APK 编译；设备检查只运行 `PlayerStabilityDeviceTest`，覆盖 0/20 间距、收藏选择/取消、横竖视频、3 次全屏往返、4 次媒体切换、owner 更换、同实例进度/倍率/A–B 和销毁释放。实际结果见[同提交 CI 证据](https://github.com/Milenal82/sakugapp/blob/evidence/maintenance/report.json)，未运行的用例不算通过。

未验证连续数小时使用、全部实体设备及厂商解码器；高分辨率逐帧分析、系统内存压力等仍需结合真实崩溃栈观察。不声称彻底修复所有崩溃。
